# refusals.txt - what the system's own MPSGraph does with the questions of the gather family that
# graph-cases.m cannot ask, one process each. It is the measurement behind the rows of the methods that take
# their parameter fed and behind the rows of the ones the port refuses with NSInvalidArgumentException.
#
#   question  the exit status of the process (134 is SIGABRT, 139 is SIGSEGV)
#   what      the text the framework's own diagnostic must carry, or - for a process that answers - the
#             shape it answers
#
# run.sh asks each of these in a process of its own and fails a question whose exit status or whose
# diagnostic is not the one written here, so a release that starts answering one of the five fed forms is as
# much a failure as one that starts refusing another. facts/MetalPerformanceShadersGraph/Core.md carries what
# each of them means and which row it is in.

# The broadcast of an axis the shape makes WIDER than the operand's: the release answers its own eight
# elements and then eight zeros, and the pattern the destination was filled with is not among them.
broadcast-wider 0 4x4
# An axis the shape ADDS at the front repeats the whole operand.
broadcast-added 0 2x2x4
# An aligned axis NARROWER than the operand's: the release keeps the operand's own extent and answers the
# operand's bytes, which is what "the result takes the larger of the two extents" is measured on.
broadcast-narrower 0 2x4
# An extent of zero is a shape with no elements in it, and the release takes the process down building it.
broadcast-zero-extent 134 device may not be nil

# The five FED forms. Each takes the release down, so none of them is a case and each is a measurement in the
# row of its own method.
fed-flatten-axis 134 NDArray dimension length > INT_MAX
fed-broadcast-shape 139 -
fed-reverse-axes 134 non constant axes tensor
fed-squeeze-axes 134 NDArray dimension length > INT_MAX
fed-expand-axes 139 -

# The forms the port refuses, each with the release's own words.
squeeze-not-unit 134 Failed to infer result type(s)
flatten-axis-outside 134 Failed to infer result type(s)
expand-axis-outside 134 Failed to infer result type(s)
# A transpose naming an axis outside the rank is the one the release does NOT refuse: it builds a tensor whose
# shape is nil and writes nothing at all, which the port cannot reproduce and raises instead.
transpose-axis-outside 0 (null)
reverse-axis-outside 134 invalid axis: 5, axis must be in range
# A permutation that is not a permutation of the operand's axes.
transpose-short-permutation 134 perm tensor length must equal input tensor rank

# The forms with an empty array or no axes at all, each of which the port answers and each of which says what
# "none" means in this family - unlike the reduction family, where a nil is every axis and an empty array none.
reverse-axes-empty 0 2x4
squeeze-axes-empty 0 1x2x4
expand-axes-empty 0 2x4
# A transpose naming the same axis twice is the identity.
transpose-same-axis 0 2x3x4

# The reshape's own three questions. The fed form is a fed parameter like the five above and is asked here for
# the same reason; the other two are the shapes the header's own words rule out.
reshape-fed-shape 139 -
# A volume that does not match: the release builds the tensor the caller asked for - the shape line prints 1x7 -
# and its own compiler refuses it, "the result shape is not compatible with the input shape"
# (MPSGraphUtilities.mm:310), and the process is gone.
reshape-volume-mismatch 134 not compatible with the input shape
# Two dynamic extents is not the one the header allows, and the release does not resolve it either: the shape
# line prints -1x-1 and the NDArray assertion takes the process down.
reshape-two-dynamic 134 NDArray dimension length > INT_MAX
# And the one the header allows where the result type can be inferred unambiguously: a 2x4 into a single -1
# answers a shape of 8 - a rank of one, which prints without an x - and the operand's own bytes.
reshape-dynamic-only 0 8

# The slice's four. A length of zero is a result of no elements, and the release builds the shape (2x0) and
# then cannot make an NDArray for it; the other three are its own compiler's refusals.
slice-length-zero 134 device may not be nil
slice-start-past-end 134 start value 9 does not fit dimension size
slice-stride-zero 134 stride cannot be 0
slice-length-past-end 134 does not fit within the dimension size

# THE SLICE FAMILY'S OWN ELEVEN ROWS. What is measured here is the family in its three directions - the
# masks, the gradient and the update - and what each of the eleven methods of 18.2's fed forms and of the
# gradient's fed shape does to a release that cannot use a shape which arrives as data. Every question here
# is asked in a process of its own and every one of them is a measurement in the row of its own method.
#
# A masked start is ZERO, so a start of 9 with an end of 0 asks for a result of no elements, which the
# release builds and then cannot make an NDArray for.
slice-mask-start-empty 134 device may not be nil

# The three FED slice forms of 18.2, and the floating point one beside them. All four print the same thing
# first: a result shape of -1x-1, which is the release's own way of saying it could not resolve the shape it
# was given, and then the process goes. The exit status depends on the destination the caller hands it -
# measured, SIGSEGV (139) into a 2x4 destination and "NDArray dimension length > INT_MAX" (134,
# MPSNDArray.mm:759) into a destination of one element - so the status here is this harness's and the shape
# line is what every destination agrees on.
slice-fed-ends 139 result-shape -1x-1
slice-fed-sizes 139 result-shape -1x-1
slice-fed-float32 139 result-shape -1x-1

# The gradient whose forward input's shape is FED rather than a constant: the release's own result tensor
# carries no shape at all, before the run and after it, and the process writes the gradient's element 0 into
# the destination's element 0 and nothing else, whatever the destination's shape is. This is why the four
# gradient rows are carried with a constant shape in the cases and name this measurement in their text.
slice-gradient-fed-shape 0 result-shape nil
slice-gradient-fed 0 result-shape nil
# Three gradients the release's own compiler will not build: a squeezeMask (alone and with the mask it pairs
# with), and a stride above one.
slice-gradient-squeeze 134 Optimize Original Module MLIR pass manager failed
slice-gradient-stride2 134 Optimize Original Module MLIR pass manager failed
# A gradient of one row where a startMask over axis 0 makes the region two rows: the release's own words are
# "'mps.strided_slice_gradient' op `grad_input`[0] = 1 should match dimension size: 2 deduced from
# `fwd_shape'", which is the check this port makes where the graph is built.
slice-gradient-shape-mismatch 134 Optimize Original Module MLIR pass manager failed

# The update's own questions. An endMask and a squeezeMask are refused on an update, and an update whose
# shape is not the region's is refused: wider in the NDArray's own words, narrower in the compiler's. The
# port refuses all three where the graph is built.
slice-update-end-mask 134 Optimize Original Module MLIR pass manager failed
slice-update-squeeze-mask 134 Optimize Original Module MLIR pass manager failed
slice-update-shape-wide 134 initWithBufferImpl
slice-update-shape-narrow 134 Optimize Original Module MLIR pass manager failed
# And the one fed form of the family the release answers, which is the whole of what separates 18.0's fed
# update from the seven fed parameters it cannot build a graph over: the starts, the ends and the strides
# arrive as int32 of shape [2] and the answer is the written-down form's answer byte for byte.
slice-update-fed-answer 0 0000c842000080bf000000c00000c8430000fa430000164400002f4400004844

# THE PAD AND THE TILE'S OWN REFUSALS, each measured on this host's own MPSGraph and each a process of its
# own. Every rank-2 pad and tile of the family answers; what is here is what the release does not.
# The two periodic modes, refused by name and after the result tensor has been built.
pad-periodic 134 Unsupported paddingMode
pad-antiperiodic 134 Unsupported paddingMode
# A MIRROR that reaches past the axis it mirrors: a left padding of three on an axis of extent two. The clamp,
# the zero and the constant answer the same padding, so it is the mirror the release's own compiler refuses
# ("Optimize Original Module MLIR pass manager failed"), and the port refuses it where the graph is built.
pad-reflect-past-extent 134 Optimize Original Module MLIR pass manager failed
# THE TWO MIRRORS' OWN LIMITS, which are different and neither is "the axis's own extent". Measured over
# extents one, two and three, on the left and on the right, over every padding from one to five: a REFLECT
# answers up to the axis LESS ONE and a SYMMETRIC up to the axis ITSELF, and the release's compiler says so
# with its own words - "'mps.pad' op padding values too large at axis 0, max padding is N, got M"
# (MPSGraphUtilities.mm:956), where the maximum it prints is 0 for a reflect on an axis of ONE and 1 for a
# symmetric on the same axis. So over an axis of one element the reflect reaches nothing at all and the
# symmetric reaches its own edge, and one element of padding past either is refused.
pad-thin-reflect 134 max padding is 0, got 1
pad-thin-symmetric 134 max padding is 1, got 2
# A DESTINATION NARROWER THAN THE RESULT, which is what the two rank-3 pad entries used to be recorded as.
# The destination this branch builds is the OPERAND's shape and the buffer is the OPERAND's bytes, while the
# result is bigger: a 4x5x6 into a 2x3x4's 96 bytes at rank of three, and a 4x6 into a 2x4's 32 bytes at rank
# of two. Which mode answers and which refuses is the measurement, and it is per mode and per rank - the two
# mirrors at rank of three are refused by the release's own multiary kernel ("Invalid KernelDAG, equalShape

# every mode writes what fits. Neither is a refusal of the PAD: asked into a destination of the RESULT's own
# shape the same pad of a rank of three answers in every mode, which is what graph-cases.m's pad-rank3-clamp
# and pad-rank3-symmetric compare - so the pad of a rank of three is a case and not a refusal, and these
# entries are named for the shape of the destination rather than for the rank.

# The concat and stack family, whose result is SEVERAL operands. Both refusals are the release's own
# compiler refusing to build the graph, and the message is its own: an axis outside the rank, and operands
# whose shapes differ anywhere but the axis they are laid along. The header says the inputs must be
# "broadcast compatible" and the release does not take it at all - which is why concat-thin-axis0 in
# graph-cases.m is a case (an extent of one ON the axis laid along is one element of the result, not a
# repeat) and this pair is a refusal (an extent of one anywhere else is not taken).
# The two axis refusals carry different messages because the release builds a stack out of an expanded
# dimension per operand and then a concatenation, and the expanded dimension is what names the axis first
# (MPSGraphUtilities.mm:3237) where the concatenation names it for a concat (MPSGraphUtilities.mm:748).
concat-axis-outside 134 invalid axis tensor: [2], axis must be in range -rank <= axis < rank, rank = 2
concat-interleave-axis-outside 134 invalid axis tensor: [2], axis must be in range -rank <= axis < rank, rank = 2
concat-shapes-differ 134 invalid input tensor shapes, all input shapes must match except at axis
stack-axis-outside 134 invalid axis: 3, axis must be in range -|rank| <= axis < |rank|
stack-shapes-differ 134 invalid input tensor shapes, all input shapes must match except at axis
# MIXED DATA TYPES, the header's other sentence, measured rather than assumed: the result tensor carries the
# FIRST operand's data type and the release's own COMPILER then refuses it, so the port agrees with the
# release about the tensor and the refusal is a compiler's, not the graph's.
# The EMPTY array is NOT here: it is not a refusal at all, and refusals.m's own branch for it is gone. It is
# two cases of the differential instead (concat-empty and stack-empty in graph-cases.m), because the release
# answers it - a result tensor of nil shape and float32 - and there was nothing to record as a refusal.
concat-mixed-types 0 result-data-type 0x10000020
