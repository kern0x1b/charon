# class-name-allowlist.txt - names the check-class-names.py scan deliberately does not report.
#
# ONE NAME PER LINE, then why. A line is a name the registry prose uses that is NOT a claim that the
# port defines a class of that name, and so cannot be the defect the scan looks for. Anything not
# here is reported, which is the point: this list is what keeps the check green AND honest, rather
# than the check being narrowed until it reads a thousand English sentences and misses the very
# mistake it was written for.
#
# NOTHING IN HERE IS A CLASS NAME WITH A PREFIX OR SUFFIX LOST. Those are defects and they are
# FIXED, not listed: the twenty descriptor rows and the two pipeline-buffer rows that said
# "CharonMTL<Name>" and then "<Name>", and the five TypeTree rows that said "FunctionLog",
# "FunctionLogDebugLocation", "LogContainer", "FunctionDescriptor" and "FunctionConstant". An
# earlier version of this file listed those five, with a reason claiming the port defines
# CharonMetalFunctionDescriptor and CharonMetalLogContainer - and that reason was ITSELF FALSE,
# because Metal/MTLReflection14.m:178 implements MTLFunctionDescriptor and MTLReflection10.m:72
# implements MTLFunctionConstant, under Apple's own names. A false sentence in a list of excuses is
# worse than no list, so the five are gone and the rows are corrected.
#
# WHAT IS LEFT IS PROSE, AND EVERY ENTRY SAYS WHICH PROSE.

# THREE NAMES THAT ARE NOT NAMES IN THIS SDK AT ALL, re-derived from SDK 16.4 rather than excused.
# They are fragments of real names written in another series' prose, so they are the same KIND of
# defect this series has been fixing, in rows this series does not touch. They are listed, and
# flagged here in one place, rather than fixed: the rows are CoreData's and AVFoundation's.
#
#   NSAscending   zero occurrences in every header of SDK 16.4. The Core Data sort order is
#                 NSSortDescriptorAscending, declared in CoreData.h, and the row's prose has lost
#                 the NSSortDescriptor prefix.
#   NSEntity      zero occurrences in every header of SDK 16.4. The Core Data class is
#                 NSEntityDescription, declared in CoreData.h, and the row's prose has lost the
#                 Description suffix.
#   CFRetained    zero declarations in SDK 16.4. The word appears once in the whole SDK, inside
#                 AVAssetImageGenerator.h's own doc text, so the row's prose is quoting a word out
#                 of Apple's documentation rather than naming a type.

NSEntity # a fragment of NSEntityDescription; absent from every SDK 16.4 header
CFRetained # no declaration in SDK 16.4; the word occurs once, in Apple's own doc prose
